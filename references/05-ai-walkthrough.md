# AI 从零带做指南｜Claude 网络、账号与订阅

本章是当前阶段的操作指南。带做先运行 `python3 scripts/workflow.py next`，按返回阶段读取对应小节，取得结果后提交控制层。阶段顺序与完成判定统一见[控制层](17-workflow-controller.md)。

**把这个项目文件夹或 SKILL.md 交给 AI，就可以开始。**

不需要另写提示词。AI 会先问准备使用的设备有没有登录过被 Claude 封禁的账号，再按需要处理旧登录残留，了解设备和进度后带您逐步操作。有工具且您已授权时，AI 会操作并检查结果；需要您手动操作时，再发截图或告诉它看到了什么。看不懂就说“我不懂，讲细一点”。

仓库已公开，不需要申请权限。如果 AI 暂时读不到 GitHub，下载项目 ZIP、解压后交给 AI。下面的内容就是完整的带做说明。

## 给 AI：读完后，直接开始带用户操作

用户发来仓库链接开始或恢复带做，先执行[链接交付启动流程](12-latest-start.md)，实时下载并校验最新完整包，再从返回目录完整读取 SKILL.md 及正文。失败时暂停带做，不复用旧教程。只有本地文件夹或已完成本次链接启动的日常继续，才执行下面的更新检查。用户明确提出其他任务时，按其要求处理。

按 `SKILL.md` 的启动规则执行 `python3 scripts/update.py check`。脚本在 24 小时内复用缓存，过期后下次调用重新联网；客户要求立即重查时使用 `check --force`。发现新版后，先回答客户当前步骤，在本次调用的首个回答末尾展示返回的 `update_notice`，例如“已有最新更新（v1.0.10），建议更新。”同一次连续带做不逐条重复，下一次调用未更新时仍提醒；连续带做跨过 24 小时后的首轮重新检查。未得到新版结果不能编造提醒，也不能把检查失败说成已是最新版。客户明确同意后才更新，更新成功后不再显示旧提醒。

你正在协助一位完全没有服务器、代理和终端经验的用户。用户把这份文档交给你，就是希望你按照这里的顺序，结合配套教程，从他当前的进度开始，一步步完成配置。请直接开始带做，不要只总结文档，也不要让用户再写一遍提示词。

目标是先确认设备是否登录过被封禁的 Claude 账号，安排适用的本地登录残留清理／iPhone 重装，再确认设备和 Google 账号准备情况，再配置电脑网络和浏览器；浏览器通过后直接进入手机，检查 Apple 账户与等待安排，在手机用 Google 登录并完成 Apple Pro 订阅，手机订单和权益确认后结束交付。Claude Code 教学不属于交付主线。已经完成的部分先确认结果，再跳过。

不要一开始连续问十几个问题。Google 账号与 iPhone 前面就确认；Apple 账户和礼品卡在手机阶段单独问，下载小火箭有需要时提前准备。用户已经做到一半时，让他发当前页面或口述已完成的部分，从那里接着走。

## 2. 每次只带做一小步

每次围绕一个小目标，按 `SKILL.md` 的“每一轮怎么带”区分代做与手动指导。有工具且已获授权时，连续完成可代做的步骤并自行验收，反馈后按顺序推进；不把每次点击变成一次用户确认。用户手动操作时，最多给两三个连续动作，简短说明下面四项，等实际反馈再继续。关键操作仍按 `SKILL.md` 的“图文带做”展示对应配图，不因代做而省略用户需要看的说明。

**当前进度：**第几阶段，正在做什么。

**现在这样做：**打开哪个软件或页面，点哪个按钮，在哪个位置填写什么。

**完成后应该看到：**页面、状态或输出中能确认成功的具体内容。

**做完告诉我：**需要用户发哪一处截图，或者口述哪一项结果。

解释要落到操作上。不要只说“SSH 登录服务器”“导入节点”“配置代理”。要说清楚终端在哪里打开、命令粘到哪里、哪些字段换成用户自己的值。每次给命令都标明：是在电脑本机终端执行，还是在已经登录 VPS 的远程终端执行。

用户发截图后，先判断当前页面和结果，再给下一步。页面跟教程不同，就根据当前界面调整；有报错就先解决当前报错。用户说“不会”“找不到”时，把这一小步再拆细，不要原样重复。

需要用户选择、授权、本人验证或确认付款，以及章节明确要求确认时，告诉他在哪个页面接手，记录当前步骤和待确认项；密码、验证码不要求发到聊天里。没有工具、无法观察结果或用户希望自己操作时，用截图或口述带做。报错或结果不明确先排查，不能自动标记完成；用户接手结束后重新观察结果，再继续。

使用浏览器工具带做时，遇到人机验证，只请用户在页面完成验证并回复“好了”。收到回复后，自行重新读取页面，继续查找入口、核对套餐；按钮名称以当前页面为准。能直接查看页面时，不再让用户代找入口或发送同一页面的截图。工具无法查看或操作该页面时，再改为截图或口述带做。

## 3. 按这个顺序带做

### 3.1 购买 VPS

VPS 选型直接按默认商家、洛杉矶机房与目标套餐推进，不询问用户主要在哪个国家或地区使用，也不把所在地、城市、运营商作为默认选型的前置问题。用户主动提出特殊需求时再针对该需求调整；node_timezone 从所选节点机房城市取得。商家注册表中的本人资料由客户在实际注册步骤填写。

**选定搬瓦工或 AKILE 后，主动读取[注册与购买图解](09-vps-purchase.md)。**注册／下单前就向用户展示当前步骤对应图片，同时给该商家相关 PDF 链接；不要等用户索要，也不要只发文字或让他自己翻 PDF。根据当前进度逐张展示，账户资料、验证和付款由用户本人完成。已有账户／服务器跳过已完成部分。套餐与费用仍按本节确认，开通后再进入 3.2。

进入购买 VPS 或购买账号的阶段时，先主动告诉用户：“教程首页已经放了 IP 检测工具和购号网站，如果你需要这些，可以直接从这里打开。”同时提供 [IP 检测](https://ip.net.coffee/claude/) 和[原有购号网站](https://chuhai91.cc)。用户需要 Google 账号时，一并给出补充渠道 [GmailBuy](https://gmailbuy.com/)；需要 Apple ID 时，一并给出补充渠道 [xintaikeji](https://xintaikeji.eu.org/)。按当前账号类型展示对应渠道，不混淆 Google 与 Apple 账号，商品信息按实际页面核对。不要只把入口放在目录里等用户自己发现，也不用要求每个人都购买账号。

阅读《纯净魔法从零部署》的购买部分。先确认用户有没有服务器；没有就按 DMIT → 搬瓦工 → AKILE 的顺序核对目标套餐，选择系统并下单。已买服务器的用户先核对现有配置，不让他重新购买。

**选购基准：**教程截图是 DMIT 洛杉矶 AN5 Premium 的 LAX.AN5.Pro.TINY：9.99 美元/月，1 vCPU、2 GB 内存、20 GB SSD、1 个 IPv4、1000 GB 流量、1 Gbps 带宽。先接近洛杉矶 AN5 Premium 的大陆优化线路，再匹配 CPU、内存、磁盘、独立 IPv4、流量和带宽，最后列价格；9.99 美元不是备选预算上限。目标是能自行登录、安装 Linux 软件并部署节点的 VPS，不能替换成机场订阅或成品代理服务。

**默认顺序：DMIT → 搬瓦工 → AKILE Cloud。**DMIT 目标套餐缺货时，看搬瓦工 USCA_9 的 1 GB 档（原核对为 49.99 美元/季）；搬瓦工目标套餐也缺货时，再看 AKILE LAXPremium-Mini（原核对为 79.99 元/月）。AKILE 从 https://akile.ai/ 进入“云服务器 → 美国 → LAX Premium”。按[网络教程的套餐对照](01-network.md)检查当前库存与费用，每次给出当前顺位的首选、官网入口和下一步。默认 DMIT 月付、搬瓦工季付、AKILE 月付，明确本次实际付款总额、覆盖时长及续费金额；用户明确要求长周期时再比较。三家目标套餐都缺货时，确认等待或在这三家内比较同线路其他套餐。已有 VPS 先核对复用，用户主动指定商家或预算时按其要求继续。

按网络用途核对已选 VPS 的线路、配置、流量、库存、付款周期与总额，用户确认后继续购买。

### 3.2 登录服务器，部署并导出节点

按用户系统指导登录 VPS，再依次完成系统准备、3x-ui 面板、防火墙、VLESS + Reality 配置和节点导出。每个环节单独带做，不要一次扔出整套命令。使用当前服务器的实际信息，不照抄教程截图里的 IP、密码、端口或密钥。

新交付固定使用 Karing `1.2.25.2802`、服务端 Xray `26.7.28`、REALITY `minClientVer=1.0.0`、目标 `www.cloudflare.com:443` 与两端 SNI `www.cloudflare.com`。AI 使用 `scripts/download_karing.py` 和网络部署脚本直接完成下载、配置与核验；已有运行正常的设备沿用当前配置。

**完成标志：**用户能登录面板，节点已创建，并拿到可用于客户端导入的节点链接或二维码。

### 3.3 配好电脑网络

先读[网络教程](01-network.md)的“配置期间先保住 Codex 的网络”。Mac 安装和配置 Karing，Windows 按 [Windows 专章](10-windows.md)使用 v2rayN。保持旧 VPN 为 Codex 提供网络，先通过新客户端本机入口单独测试新节点；测通后安排切换，新线路接管后才核对系统代理关闭、TUN／Tunnel 开启、全局代理开启。切换后重新检查实际出口，并确认 Codex 能收到新回复，再继续。确有冲突必须先断旧 VPN 时，提前给出具体手动恢复步骤后执行；后续断线测试同样如此。不要把 Mac 按钮路径直接用于 Windows。

如果后台测试通过，但停旧 VPN 后 Codex 持续重连、没有新回复，或用户反馈新节点不能用，先恢复旧连接，随后直接执行[网络教程第十节](01-network.md#十karing-reality-握手失败)的修复步骤。每完成一项立即复测，失败继续下一项，成功返回网络交接验收。Windows 按其实际客户端与内核修复。

**Mac 连接出错，由 AI 连续修复 Karing。**向用户简短说明“我先按已有方案修复，完成后检查实际连接”，直接读取配置并执行。兼容性判断、日志读取、参数校正、版本调整和复测由 AI 完成；需要用户操作时，只给出当前工具无法完成的具体动作。

Mac Karing 按固定顺序执行：适用时先试 `mixed → gvisor`；无效或不适用，自动校正参数、服务与时间；仍失败，备份后执行第十节的已验证的 REALITY 组合，重新导入并验证请求、出口及 Codex 新回复。成功即继续交付；已尝试无效的步骤直接跳过。

**完成标志：**客户端连接正常，实际访问的出口符合所选线路；检查 Claude 相关流量的去向，并通过受控的断线检查确认不会自动直连。把连通、出口、断线这三项逐项确认后，再进入浏览器配置。

### 3.4 配好 AdsPower 浏览器

阅读《指纹浏览器与 iPhone 网络配置》的电脑部分。Mac 这条路线是：AdsPower → 本机 HTTP 代理入口 → Karing → DMIT VPS。先找到本机代理客户端实际开放的 HTTP 地址和端口，再创建 AdsPower 环境并填写。Windows 则确认 v2rayN 实际开放的 HTTP／混合入口，系统选 Windows，按 Windows 专章检查时区。

VLESS 节点链接导入代理客户端；AdsPower 填的是本机 HTTP 入口。HTTP／SOCKS5 同时可用或客户端提供混合端口时优先 HTTP，新节点独立测试也遵循此顺序；HTTP 先排查仍不可用／不兼容时，才按浏览器章节使用经过实测的 SOCKS5 备选并记录原因，不调整 TUN 的 mixed/gvisor。VPS 的 SSH 账号密码不能拿来当浏览器的代理账号密码。浏览器内核选 AdsPower 当前支持的稳定版本，硬件参数尽量与本机一致，语言和时区按对应教程设置。

**完成标志：**在新建的浏览器环境里能正常访问网页，并检查实际出口、语言和时区。注册前在这个环境打开[Claude IP 纯净度检测](https://ip.net.coffee/claude/)，按汇总首页建议检查评分。

在同一个环境完成三站检查：NetCoffee 建议约 80 分或更高；[Ping0](https://ping0.cc/) 风险值低于 30 可作可接受参考、优先低于 25；[Scamalytics](https://scamalytics.com/ip) 风险值最好低于 10。按浏览器章节 1.4 分别记录当前出口的结果、时间与脱敏截图，不混用量表；缺失结果写“未验证”。

### 3.5 手机网络配置 → 时区和定位设置 → 验收

电脑浏览器检查通过后，主动进入手机阶段，不先让用户在电脑网页注册 Claude，不再问“先使用还是配置手机”。手机主要用于首次登录和 Apple 订阅，日常使用电脑的 Claude 桌面端或 CLI；网页登录与授权使用 AdsPower。Android 用户先完成适用手机网络与浏览器出口检查，再进入[安卓官网 Google Pay 分支](11-android-web-pay.md)：先告知案例较少及作者反馈的封号后无法退款风险，用户接受后在手机浏览器打开官网登录和订阅；不要求准备 iPhone，不套用 Apple 内购。

1. Mac＋iPhone 优先连接 **iPhone 镜像 + Codex Computer Use**，按浏览器章节 2.1 排查兼容性、账户、授权和连接问题，尽可能修复后由 Codex 操作。确实不可用时记录原因，再采用其他可用工具或逐步手动带做。Windows＋iPhone 默认对应图解、截图／口述带做；有实际可用手机工具再代做，不要求 Mac 原生镜像。
2. 准备小火箭，导入电脑已经验证的同一服务器节点；**全局路由默认选“代理”**，开启连接并核对系统 VPN。已有可用小火箭直接复用，不重复购买。尚无小火箭、需要购买时，在 `phone_proxy` 提交 `client_available=false`，提前处理 Apple 账户；新号先在客户手机 App Store 登录，记录账号标识、首次登录时间和已展示提醒，默认建议约两天后再购买，客户明确选择立即继续时记录其选择。Claude 充值、订阅仍留到后续账户检查完成，不能因缺客户端跳过手机网络。
3. **先完成时区和定位设置。**主动按[具体设置路径](02-browser-iphone.md#23-电脑和手机时区定位设置)展示并带做：Mac 关闭自动时区、选择本次方案的城市（节点城市或台北），关闭系统服务“设定时区”；Mac 定位总开关保持原有状态，Claude 网页位置权限与 AdsPower 地理位置设为禁止。iPhone／iPad 按手机步骤关闭自动设置、选择时区、关闭“设定时区”和定位总开关。Windows／Android 按对应专章展示时区和定位入口，完成后返回设置页面复查。先询问一次“跟随节点（程序和作者推荐）／台北”，再直接展示攻略里的 Mac 和手机设置步骤；已有选择和设置结果复用。
4. 完成手机网络验收：核对同一节点和实际出口、三个检测网站、IPv6／DNS、排除路由、Wi-Fi／蜂窝网络和断线行为。复用第 3 步设置结果，将电脑、手机与 AdsPower 时区并排核对。语言可保留中文；客户愿意改英文时，电脑与手机一起改，并说明菜单会变成英文。

小火箭全局超时、节点无法使用或网页打不开时，优先按[小火箭 TLS 指纹案例](02-browser-iphone.md#221-小火箭全局超时先试-chrome-140)直接给出 `Chrome 140` 的首个尝试步骤，不先索要诊断包或要求判断适用性；记原值、修改重连、复测，有效保留，无效恢复。找不到选项再看截图；Windows＋iPhone 按实际页面手动操作，不把 TCP 延迟或“已修改”当作通过。

**完成标志：**电脑与手机网络、时区和定位分别记录完成结果，AdsPower 时区和地理位置设置完成。将当前阶段实际观察提交[统一控制层](17-workflow-controller.md)，程序依次返回支付准备、App、登录和订阅任务，复用已完成的账户准备与登录。

### 3.6 确认美区 Apple 账户、礼品卡和等待安排

本节及后面的 iPhone App 登录、Apple 内购步骤仅适用于 iPhone。安卓在手机网络自检通过后按[安卓官网 Google Pay 基础指引](11-android-web-pay.md)完成风险提示、官网登录和付款，再直接接 3.9 完成交付；不进入 Apple 等待、礼品卡或退款流程。

网络、时区和定位检查完成后先说明“这套 iPhone 礼品卡订阅路线使用美区 Apple 账户”，再单独问：“您已经有美区 Apple 账户了吗？”有的话继续问是一直自己用的老号、新注册，还是刚买／刚接手的账号，按实际回答记录 `account_origin`。新注册和新购买／接手统一按新号提醒，展示完整风险说明和等待安排后再确认礼品卡或余额。已有答案直接复用。

没有美区 Apple 账户时，并列提供自己注册与购买两种方式，由用户选择。注册／改区按 Apple 章节；购买提供[原有购号网站](https://chuhai91.cc)和 [Apple ID 补充渠道 xintaikeji](https://xintaikeji.eu.org/)，确认可控制账号。仅在 App Store 使用购入账号，不替换设备的 iCloud 账户。

确认新号、以及买号或注册完成后，立即展示 [Apple 章节](03-apple.md#充值和订阅前先确认-apple-账户情况) 的醒目警示：能标红就标红，普通聊天用 🔴＋加粗独立块。明确先在自己手机 App Store／“媒体与购买项目”成功登录一次，不更换 iCloud；从实际首次登录使用起点正常使用**约两天**，暂不购买礼品卡、充值或订阅。说明客户反馈中立即充值付款较容易遇到购买限制，可能要找人工客服及等待 72 小时，具体按客服答复；不写成必然封禁。长期自用老号无购买限制可继续。已有余额不追加充值，已有礼品卡按等待安排继续。记录手机商店登录结果、实际首次登录使用起点、时区、醒目提醒是否已展示及预计继续日期，下次不重新计时。购买已受限时转人工支持，不拿新号等待代替客服安排。

**进入订阅的条件：**美区 Apple ID 可用、当前没有购买限制，余额／礼品卡已安排。新号默认建议从本人手机首次 App Store 登录成功起等约两天；明确选择现在继续时记录选择后接 3.7。选择等待的保留原起点，到期继续，已有记录直接复用。

### 3.7 登录前提醒，再在手机用 Google 登录 Claude

先读取登录前衔接检查结果，完成剩余设置后复用早期准备的 Google 账号；没有则回到[Google 账号准备](08-google-account.md)。登录前再简短提醒：手机主要用于登录和付款；不要在默认浏览器打开 Claude；相关邮件可能有跟踪像素，邮件和登录链接放到已配置的环境处理。日后 Claude Code 弹出的授权网页，也应把完整链接转到已配置的指纹浏览器。

先读取 3.6 的美区 Apple ID 和等待安排与客户选择记录；就绪后保持手机目标节点开启，主动提醒下载并核对 Anthropic 官方 Claude App，在未登录状态结合客户端日志核对可观察到的请求路径。使用实际页面的 **Google 登录入口**，由用户完成 Google 账号、密码和两步验证。两步验证按账号章节指导，密钥、密码和验证码不发到聊天。首次登录按页面完成必要设置；不另行发起电脑网页注册或默认创建 Proton 邮箱。

用户说“登录好了”时，确认当前阶段只是登录完成，下一步直接订阅 Pro；用户未反馈则保留待确认，不自行标记交付完成。

**默认直接订阅：**美区 Apple ID 等待安排已确认、环境配置完成后，手机 Google 登录成功就进入 3.8。客户主动提出免费体验时再安排。

### 3.8 图文引导充值并订阅 Pro

主动确认等待已到期或客户已明确选择现在继续，再按 [Apple 章节](03-apple.md)逐步引导，不等用户主动提礼品卡。兑换用该章图 15，确认官方 App 用图 16，订阅付款用图 17；先核对图片与当前页面对应，再在聊天展示，每次一个小目标。Google 登录没有对应截图时按实际手机页面指导，不用旧的网页邮箱注册图冒充。

**默认先推荐 Pro，标价 20 美元／月，实际费用按页面和税费确认；不主动推荐首次就上 Max。**用户已有余额则跳过充值；要充值时先核对地区、所需金额与税费。用户本人确认付款。

付款后核对 App Store 订单、当前 Claude 账号和 Pro 权益。失败时停止重复充值，按实际错误进入 Apple 人工支持，记录客服等待起点和重试时间。客户只说“能用了”，还需明确是登录成功还是订阅到账；没有反馈保留未验收状态。

### 3.9 手机订阅到账，完成交付

核对 App Store 订单和当前手机 Claude 账号的 Pro 权益，两项确认后，直接展示本章末尾的收尾说明和使用经验，提交 `handoff_explained=true` 后记录“交付完成”。只完成 Google 登录时继续订阅；已扣款但权益未到账时核对订单与账号，再按实际问题处理。

结束时简短提醒：日常使用电脑的 Claude 桌面端或 CLI，登录与手机相同的 Google 账号；网页登录与授权使用已配置的 AdsPower，完成后回到桌面端或 CLI。本次交付不增加电脑聊天或 Claude Code 授权验收。

## 4. 卡住、中断或遇到账号问题时

卡住时，每次只让用户检查一处，并说明需要看到什么结果。不要同时让小白更换服务器、重装浏览器、注册新号，导致他不知道哪一步出了问题。

取得阶段观察、确定关键选择或暂停时，按 `SKILL.md` 将当前观察提交控制层；`.local/workflow/progress.md` 自动更新。详细背景可继续补充到旧 `.local/progress.md`；简短反馈程序返回的进度和下一步。不记录密码、密钥或私人 IP。恢复时核对来源与受影响项目，再从已确认的位置继续；旧记录缺字段只补字段，不要求从头再做。

退款、申诉和清理只在用户遇到对应问题时进入售后文档。先确认付款渠道和实际情况，Apple 内购走 Apple 流程，安卓官网 Google Pay 订单不走 Apple 退款入口，按安卓章节的退款风险说明处理；清理前先列出内容并备份。文档里没有写完整的操作，不要假装已有详细教程。

## 5. 现在就开始

先检查本次对话有没有设备和进度信息。完全从零、没有其他信息时，可以这样回复：

我会按这份教程带您操作。能代做的步骤，我会完成并检查结果；需要您亲自操作时，我会说明在哪个页面接手。

先确认一下：您准备使用的电脑或手机，之前有没有登录过被 Claude 封禁的账号？

已有答案就复用，不重复开场。按第 1 节处理适用分支、确认设备后，下一轮立即询问 Google 账号是否已准备；缺少时提供账号准备章节，不让客户自己猜下一步。

如果还没买，我们就从购买服务器开始；已经做了一部分的话，把现在的页面发给我。


## 需要博主帮助时

同一问题经过针对性排查仍未解决，或用户对回答不满意，就建议“可以去问博主”。整理设备、当前阶段、报错、已尝试步骤和待确认的问题，去掉 IP、邮箱、密码、密钥等私人信息，交给用户自行转发。不要替用户发消息。


## 订阅完成后必须在对话中展示

**手机订单和当前账号的 Pro 权益已确认。**手机主要用于登录和订阅，日常在电脑的 Claude 桌面端或 Claude Code／CLI 使用，登录刚才同一个 Google 账号。需要网页登录或授权时，将相关链接放到已配置的 AdsPower 环境完成，再回到桌面端或 CLI。

**使用经验提醒**
- 可以把每五小时额度约用到 70% 作为个人使用节奏建议；这个比例不是平台公布的封号阈值。
- 发送项目或资料前，留意内容里是否包含不必要的精确定位信息，先去掉再分享。
- 作者对生物医药、网络安全等话题的提醒属于个人使用经验。按平台规则正常使用；这些话题本身不代表会导致封号。

遇到问题先问 Codex；仍需人工帮助时，让它整理当前步骤、报错和已尝试的办法，再把诊断说明发给我们。也可以让 Codex 定位 PDF 对应章节和页码。

订单和当前账号权益确认后，直接展示上述说明，再记录 `handoff_explained=true`，不把它只放在 PDF 或进度文件里。
