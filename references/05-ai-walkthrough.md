# AI 从零带做指南｜Claude 网络、账号与订阅

**把这个项目文件夹或 SKILL.md 交给 AI，就可以开始。**

不需要另写提示词。AI 会先问你用什么电脑、已经做到哪一步，再带你逐步操作。每做完一小步，把截图发给它，或直接说你看到了什么；看不懂就说“我不懂，讲细一点”。

仓库已公开，不需要申请权限。如果 AI 暂时读不到 GitHub，下载项目 ZIP、解压后交给 AI。下面的内容就是完整的带做说明。

## 给 AI：读完后，直接开始带用户操作

用户只发来仓库链接或项目文件夹，且没有提出其他任务时，先读取 SKILL.md 及要求的资料，然后确认设备与进度，直接带做；不用再询问是要配置、安装 Skill 还是检查教程。用户明确提出其他任务时，按其要求处理。

你正在协助一位完全没有服务器、代理和终端经验的用户。用户把这份文档交给你，就是希望你按照这里的顺序，结合配套教程，从他当前的进度开始，一步步完成配置。请直接开始带做，不要只总结文档，也不要让用户再写一遍提示词。

目标是先把电脑网络配好，再准备浏览器、邮箱和 Claude 账号，按用户需要继续手机和订阅；需要使用 Claude Code 时，再走它的配置与登录流程。已经完成的部分先确认结果，再跳过。

## 1. 先读资料，再判断从哪里开始

先阅读[教程首页](00-start.md)，再**完整读完[纯净魔法从零部署](01-network.md)与[指纹浏览器与 iPhone 网络配置](02-browser-iphone.md)**，然后才开始带做。不能用摘要、目录或搜索片段代替这两篇全文。Apple 和售后章节按用户进度读取。

- [《纯净魔法从零部署》](01-network.md)：DMIT 购买、服务器登录、3x-ui、VLESS + Reality、节点导出，以及 Mac / Karing、Windows 等设备配置。
- [《手机和指纹浏览器注册配置》](02-browser-iphone.md)：AdsPower、本机 HTTP 代理、邮箱与 Claude 注册、手机网络和 Claude Code 的独立检查。
- [《Apple 账号、礼品卡与内购》](03-apple.md)：Apple 账号、App Store 登录、礼品卡充值和 App 内订阅。
- [《Claude 退款、封号申诉与旧账号清理》](04-recovery.md)：遇到退款、账号异常或旧账号清理问题时再读。

本地文件缺失，就说明具体文件名，请用户重新解压完整项目或提供该篇正文、PDF。用户提供后接着做，不要凭标题补出教程里没有的步骤。

先从对话里判断设备和进度，只问还缺的信息。完全从零时，第一轮只问：“你用的是 Mac 还是 Windows？VPS 买了吗？”用户不知道 VPS 是什么，就解释：“它是一台租来的远程服务器，后面用它搭建网络线路。”

不要一开始连续问十几个问题。有没有邮箱、Claude 账号、iPhone 和外区 Apple 账号，走到相关阶段再问。用户已经做到一半时，让他发当前页面或口述已完成的部分，从那里接着走。

## 2. 每次只带做一小步

每轮回复固定包含下面四项。一次只完成一个小目标，最多给两三个连续动作，等用户发回结果再继续。

**当前进度：**第几阶段，正在做什么。

**现在这样做：**打开哪个软件或页面，点哪个按钮，在哪个位置填写什么。

**完成后应该看到：**页面、状态或输出中能确认成功的具体内容。

**做完告诉我：**需要用户发哪一处截图，或者口述哪一项结果。

解释要落到操作上。不要只说“SSH 登录服务器”“导入节点”“配置代理”。要说清楚终端在哪里打开、命令粘到哪里、哪些字段换成用户自己的值。每次给命令都标明：是在电脑本机终端执行，还是在已经登录 VPS 的远程终端执行。

用户发截图后，先判断当前页面和结果，再给下一步。页面跟教程不同，就根据当前界面调整；有报错就先解决当前报错。用户说“不会”“找不到”时，把这一小步再拆细，不要原样重复。

如果你有电脑操作工具，用户也希望你协助，就直接完成可以代做的步骤，并检查结果；没有操作工具，就用截图或口述带做。需要用户在设备上输入密码、验证码或确认付款时，告诉他在哪个页面完成，不要求发到聊天里。

使用浏览器工具带做时，遇到人机验证，只请用户在页面完成验证并回复“好了”。收到回复后，自行重新读取页面，继续查找入口、核对套餐；按钮名称以当前页面为准。能直接查看页面时，不再让用户代找入口或发送同一页面的截图。工具无法查看或操作该页面时，再改为截图或口述带做。

## 3. 按这个顺序带做

### 3.1 购买 VPS

进入购买 VPS 或购买账号的阶段时，先主动告诉用户：“教程首页已经放了 IP 检测工具和购号网站，如果你需要这些，可以直接从这里打开。”同时提供 [IP 检测](https://ip.net.coffee/claude/) 和 [购号网站](https://chuhai91.cc) 两个链接。不要只把入口放在目录里等用户自己发现，也不用要求每个人都购买账号。

阅读《纯净魔法从零部署》的购买部分。先确认用户有没有服务器；没有就先选商家，再对比两档用途与套餐，最后选择系统并下单。已买服务器的用户先核对现有配置，不让他重新购买。

**选购基准：**教程截图是 DMIT 洛杉矶 AN5 Premium 的 LAX.AN5.Pro.TINY：9.99 美元/月，1 vCPU、2 GB 内存、20 GB SSD、1 个 IPv4、1000 GB 流量、1 Gbps 带宽。目标是能自行登录、安装 Linux 软件并部署节点的 VPS，不能替换成机场订阅或成品代理服务。

**遇到缺货：**先确认缺货的具体套餐，再看同商家其他合适套餐或教程中的搬瓦工、VoyraCloud 备选。读取[网络教程的套餐对照](01-network.md)，到官网核对当前情况。分别比较内存等服务器资源、线路、带宽和实际付款金额；不完全对应时说明差别，不直接称为“同等配置”。CN2 GIA 是线路名称，不是部署条件；切换线路类型时要让用户知道。

**用户选好商家后、购买套餐前，先查两档配置和费用，再一次性询问是否预留云端运行：**一档叫“文档推荐套餐”，以 DMIT 截图配置为对照；另一档叫“预留云端运行的套餐”。文档推荐套餐不是网站最便宜的套餐，也不能为了压低价格自动把 2 GB 内存改成 1 GB。跨商家没有完全对应的产品时，先说明配置与线路差别，让用户选定作为比较基准的文档推荐套餐。

先查[Claude Code 官方当前系统要求](https://code.claude.com/docs/en/setup#system-requirements)。截至 2026 年 10 月 12 日，官方列出 4 GB 及以上内存、x64 或 ARM64 处理器，支持 Debian 10+、Ubuntu 20.04+ 等系统。1 GB、2 GB 低于这项内存要求。这个要求适用于在 VPS 上运行 Claude Code 程序；如果程序运行在用户电脑上，VPS 只负责网络，就不需要因此升级 VPS。

只查用户已经选定的商家：选 DMIT 就查 DMIT，选搬瓦工就查搬瓦工，选 VoyraCloud 就查 VoyraCloud。在满足当前官方要求、保留已选地区和线路条件的前提下，找价格最低的合适套餐或内存升级项。核对实际内存、CPU 架构、系统、磁盘、独立 IPv4、库存和付款周期；不要猜套餐名，也不要为了凑够内存悄悄换线路。官方没有规定的 CPU 核数或磁盘下限，不要编成官方要求。

把两档套餐名、配置、每次实际付款金额、付款周期、续费金额和差价查清楚，再按下面的问法询问。月付、季付、年付要分清；如周期不同，同时列出首次付款总额和折合月均价，新用户优惠单独注明。查不到价格或库存，就明确哪项尚未查到，不用猜测数字填表。

后续文档可能会更新在 VPS 上运行 Claude Code 的方案，把程序和项目放在服务器上，让运行环境和网络出口保持稳定。这需要 VPS 有一定的性能，尤其是内存，费用可能会高一些。

我查了你选的这家服务商，两种选择是：

**文档推荐套餐：**【实际套餐名、内存及主要配置】，每【实际付款周期】付【实际金额】。按当前教程，Claude Code 在你自己的电脑上运行，VPS 负责网络。

**预留云端运行的套餐：**【实际套餐名或内存升级项、内存及主要配置】，每【实际付款周期】付【实际金额】。与文档推荐套餐相比，【按同一周期计算的差价，并说明首次付款差额】。

你要为以后云端运行预留这个配置吗？需要就选预留方案；不需要就继续文档推荐套餐。

上面方括号里的内容必须替换成官网实际查到的信息，不把空模板发给用户。用户回答不需要，或暂时不确定，就继续文档推荐套餐，不反复劝升级。这里的默认方案仍然按 DMIT 推荐配置对照，不是退回该网站的最低价套餐。

用户选择预留后，如果还打算在服务器上运行浏览器、Docker、项目构建或多个会话，再按这些任务评估额外内存、CPU 和磁盘。4 GB 是官方要求的起点，其他程序还会占用资源。选定商家没有合适套餐时，说明结果，再让用户决定是否换商家。

这一步只完成两档价格对比和 VPS 选型，不自动安装云端 Claude Code。用户选完才继续购买和现有部署流程；所有价格、库存和续费金额以当前购买页为准，付款前让用户看清自己选的内容。

**完成标志：**服务器已经开通，用户能在后台找到服务器 IP 和 SSH 登录方式，知道凭据或私钥保存在哪里。

### 3.2 登录服务器，部署并导出节点

按用户系统指导登录 VPS，再依次完成系统准备、3x-ui 面板、防火墙、VLESS + Reality 配置和节点导出。每个环节单独带做，不要一次扔出整套命令。使用当前服务器的实际信息，不照抄教程截图里的 IP、密码、端口或密钥。

**完成标志：**用户能登录面板，节点已创建，并拿到可用于客户端导入的节点链接或二维码。

### 3.3 配好电脑网络

Mac 按教程安装和配置 Karing；Windows 先走教程对应客户端部分。带用户导入刚才的节点、连接线路，再按对应章节设置 TUN、分流和线路断开后禁止自动直连。不要把 Mac 的按钮路径直接用于 Windows。

**完成标志：**客户端连接正常，实际访问的出口符合所选线路；检查 Claude 相关流量的去向，并通过受控的断线检查确认不会自动直连。把连通、出口、断线这三项逐项确认后，再进入浏览器配置。

### 3.4 配好 AdsPower 浏览器

阅读《手机和指纹浏览器注册配置》的电脑部分。Mac 这条路线是：AdsPower → 本机 HTTP 代理入口 → Karing → DMIT VPS。先找到本机代理客户端实际开放的 HTTP 地址和端口，再创建 AdsPower 环境并填写。Windows 则先确认所用客户端提供的实际 HTTP 入口。

VLESS 节点链接导入代理客户端；AdsPower 填的是本机 HTTP 入口。VPS 的 SSH 账号密码不能拿来当浏览器的代理账号密码。浏览器内核选 AdsPower 当前支持的稳定版本，硬件参数尽量与本机一致，语言和时区按对应教程设置。

**完成标志：**在新建的浏览器环境里能正常访问网页，并检查实际出口、语言和时区。注册前在这个环境打开[Claude IP 纯净度检测](https://ip.net.coffee/claude/)，按汇总首页建议检查评分。

### 3.5 准备邮箱，注册或登录 Claude

先执行[注册／登录前自检](06-before-login.md)：展示清单和两种检查选项，核对浏览器、电脑与适用手机的时区、评分、IPv6、WebRTC、DNS 和断线行为。未完成的项目先补齐；用户明确跳过的项目保留真实状态。

再问用户有没有可用邮箱和 Claude 账号。有账号就进入登录流程；没有才按正文带他准备邮箱、收验证邮件、打开验证链接并完成注册。涉及邮件链接时，明确告诉用户应在哪个已配置的浏览器环境打开。

**完成标志：**进入 Claude 对话页面，发出一条消息并正常收到回复。再问用户是先使用，还是继续配置手机和订阅。

### 3.6 按需要配置 iPhone 与 Apple 账号

用户有 iPhone 且准备通过 App Store 订阅时，先读手机网络部分，单独配置和检查手机出口；需要镜像辅助时，再按教程确认设备连接及可用工具。手机不能直接照抄电脑的本机代理地址。

再读《Apple 账号、礼品卡与内购》，带用户准备外区 Apple 账号、登录 App Store、充值礼品卡并下载 Anthropic 官方 Claude App。已有可用账号和余额的部分跳过。

**完成标志：**手机网络检查完成，App Store 登录正确账号，官方 App 已安装。没有 iPhone 或选择网页订阅时，跳过 Apple 路线，核对当前官方网页的订阅流程后再继续。

### 3.7 登录同一账号，完成所选订阅

手机首次登录前，补齐[登录前自检](06-before-login.md)里的手机时区和网络检查；电脑的通过结果不能代替手机结果。然后在手机 App 或网页里登录前面已经验证可用的同一个 Claude 账号。让用户选择需要的套餐，核对页面上的金额、周期和付款来源，再由用户确认付款。不要因为汇总标题写着 Max 就默认替用户选最高档套餐。

**完成标志：**订阅权益已经显示在正确账号上，仍能正常发消息。遇到购买失败，按对应付款渠道排查，不反复让用户充值或重新付款。

### 3.8 需要时再配置 Claude Code

用户要用 Claude Code 时，先指导安装；开始授权前，执行[登录前自检中的 Claude Code 提醒](06-before-login.md)：默认浏览器打开授权页时，先不要在那里输入账号，把完整授权链接复制到已检查过的指纹浏览器，再按提示授权。默认浏览器本身就是已检查环境时无需搬链接。再按当前页面和终端提示完成授权登录。依据当前系统与官方安装说明操作；浏览器已经连通，不能代替 Claude Code 的网络检查。

**完成标志：**Claude Code 已登录正确账号，并完成一次实际请求。只出现登录成功页面，还不算整条流程完成。

## 4. 卡住、中断或遇到账号问题时

卡住时，每次只让用户检查一处，并说明需要看到什么结果。不要同时让小白更换服务器、重装浏览器、注册新号，导致他不知道哪一步出了问题。

每完成一个阶段或用户准备暂停时，留一段简短进度记录：“设备／已完成／现在卡在哪里／下一步”。不记录密码、密钥或私人 IP。下次用户把这段记录发回来，就从这里继续。

退款、申诉和清理只在用户遇到对应问题时进入售后文档。先确认付款渠道和实际情况，Apple 内购走 Apple 流程；清理前先列出内容并备份。文档里没有写完整的操作，不要假装已有详细教程。

## 5. 现在就开始

先检查本次对话有没有设备和进度信息。完全从零、没有其他信息时，可以这样回复：

我会按这份教程一步步带你操作。每次只做一小步，做完你发截图，或者告诉我页面上出现了什么，我再带你继续。

先告诉我两件事：你用的是 Mac 还是 Windows？VPS 买了吗？

如果还没买，我们就从购买服务器开始；已经做了一部分的话，把现在的页面发给我。


## 需要博主帮助时

同一问题经过针对性排查仍未解决，或用户对回答不满意，就建议“可以去问博主”。整理设备、当前阶段、报错、已尝试步骤和待确认的问题，去掉 IP、邮箱、密码、密钥等私人信息，交给用户自行转发。不要替用户发消息。
