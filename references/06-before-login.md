# 注册或登录 Claude 前，先检查一遍

电脑网络和指纹浏览器配置完成后，先做这一轮检查，再注册或登录 Claude。已有账号也要检查。换电脑、换浏览器环境、换节点或网络配置后，检查受影响的项目。

## 给用户看的说明

> 先确认网络和浏览器已经配好，再登录 Claude。
>
> - 指纹浏览器是否配置完成，当前打开的是不是准备使用的那个环境？
> - **Mac 时区三项是否都设置好了？**在「系统设置 → 通用 → 日期与时间」关闭自动设置时区，手动选择节点所在城市；再到「隐私与安全性 → 定位服务 → 系统服务」关闭「设定时区」。不要只确认当前显示的城市。
> - **iPhone 时区三项是否都设置好了？**在「设置 → 通用 → 日期与时间」关闭「自动设置」，手动选择节点所在城市；再到「隐私与安全性 → 定位服务 → 系统服务」关闭「设定时区」。暂时不用手机，首次登录或订阅前再补检。
> - 定位相关的时区设置可能让系统回到所在地时区，例如上海；**请确认上述开关状态，并返回日期与时间页面复查城市。**浏览器检测到的时区也要单独核对。
> - 在这个指纹浏览器里打开 [Claude IP 检测](https://ip.net.coffee/claude/)，分数是多少？教程建议 80 分以上；评分只作参考，其余项目也要检查。
> - IPv6 是否已禁用，或确认不会绕过预期线路？
> - WebRTC 是否已禁用，检测时有没有暴露其他公网出口？
> - DNS 查询有没有绕过配置的线路？
> - 节点断开或 Karing 退出后，会不会自动直连？
>
> **下一步：① 让 AI 帮我检查（推荐）　② 我提供检测截图，AI 帮我核对。**
>
> 暂时不用手机，可以先完成电脑检查；手机首次登录 Claude 前再单独检查。

## AI 怎么执行

到达注册或登录步骤时，先展示上面的短说明和两个选项，等待用户选择，不直接打开 Claude 注册或登录页面。对话工具支持选项时使用选项；否则用文字，让用户回复 1 或 2 即可。用户已明确要求检查时直接开始。

选择 1：用现有工具读取配置，在实际准备登录的浏览器环境里检测。不能操作某台设备或检测页时，只请用户提供缺失部分的截图或结果。选择 2：核对截图所属的设备、浏览器环境和检测时间；看不到的项目标记为“未验证”。不要因为截图里有高分，就替其他项目填通过。

| 项目 | 核对什么 |
| --- | --- |
| 指纹浏览器 | 环境已保存并打开；HTTP 入口与 Karing 当前配置相符，代理实际连通；检测必须在这个环境内完成。尚未配置好时回到浏览器配置章节。 |
| 电脑时区 | Mac 逐项核对：①「系统设置 → 通用 → 日期与时间」的自动设置时区已关闭；② 手动选择的城市对应实际节点地区；③「隐私与安全性 → 定位服务 → 系统服务 → 设定时区」已关闭。记录每项状态，再返回日期与时间页面复查实际城市。单独核对浏览器读到的时区，不能用浏览器设置代替系统设置；Windows 按实际系统核对，不能套用 Mac 路径。 |
| 手机时区 | iPhone 首次登录 Claude 或通过 App Store 订阅前，逐项核对：①「设置 → 通用 → 日期与时间 → 自动设置」已关闭；② 手动选择的城市对应实际节点地区；③「隐私与安全性 → 定位服务 → 系统服务 → 设定时区」已关闭。记录每项状态，再返回日期与时间页面复查实际城市。没有手机或暂不使用，记录“不适用（首次登录或订阅前补检）”，不算手机已通过。 |
| IP 检测评分 | 在拟登录的浏览器环境打开 https://ip.net.coffee/claude/，记录实际分数和检测时间。按教程“80 分以上”的建议核对；不满足建议值时先说明并排查，不写“账号一定安全”。页面不可访问、无分数或量表不同，记录“未验证”，不编造分数。 |
| Ping0 节点检测凭证 | 在同一浏览器环境打开 https://ping0.cc/，按浏览器章节 1.4 记录检测时间、节点名称、出口地区、ASN / 运营商、IP 类型、风控值、原生 IP、共享人数及脱敏截图路径。风控值与 Claude 检测分数分别记录，不混用量表；缺失结果写“未验证”。第三方标签只作辅助证据。 |
| IPv6 | 记录“已禁用 / 不可用 / 已启用”。已禁用或不可用还要核对是否确实没有浏览器 IPv6 出口；启用时检查是否沿预期线路。不能把“未测到地址”写成“系统已禁用”。发现绕行先修复。 |
| WebRTC | 查看该浏览器环境内 WebRTC 是否禁用，并实际检测是否暴露预期代理之外的公网地址。配置状态和实际测试结果分别记录。 |
| DNS | 结合浏览器安全 DNS、客户端 DNS 规则及检测结果判断查询路径。解析服务商与 VPS 不同、解析器城市不同，本身不能直接判为泄露。不能确认查询路径时标为“未验证”。 |
| 实际出口与断线行为 | 按浏览器章节 1.4 验证实际出口和目标域名路由；分别检查节点不可达与客户端退出，不允许自动直连。确认当前没有登录、付款或其他不能中断的工作后，再做断线测试并恢复连接。 |

先检查，再处理发现的问题。修改系统时区、IPv6 或浏览器配置前，说明改哪里、会影响什么并记录原值，按用户授权操作。不要为了把清单全部勾上，直接重置网络或覆盖原有浏览器环境。

**时区项必须主动提醒并逐项验收。**不要只问“时区改了吗”，也不能只凭一次显示为洛杉矶就写通过。Mac 和 iPhone 分别记录自动设置开关、手动城市、定位服务中的「设定时区」开关，以及返回页面后的复查结果。看不到某个开关时，只请用户补充该设置页的截图或在页面确认，记“未验证”；适用设备的三项设置与复查均确认后，时区项才记通过。系统版本导致路径或名称变化时按实际界面定位；开关无法调整时先排查，不把不可操作直接记为已关闭。只核对相关时区设置，不要求关闭整个定位服务或 Mac 的自动校时。设置、节点地区或网络变化后重查对应项目；时区差异不能被写成确定的封号原因。

检查完成后只展示简短表格：“检查项｜通过／未通过／未验证／不适用｜结果”。记录检测分数、时间、IPv6 实际状态和需要补做的项；公网 IP 脱敏，不保存账号、密钥或授权链接。

发现未通过或未验证的适用项目，先带用户修复或补检，再回到本表。全部适用项已完成后，告诉用户检查结果，再进入注册或登录。用户明确要求跳过时说明尚未核对的项目，保留原状态，不把跳过记成通过。网络检测只能核对配置，第三方评分不能预测封号结果。

## Claude Code 登录时的提醒

开始 Claude Code 登录前，先确认指纹浏览器检查结果仍然适用，并核对准备启动 Claude Code 的终端网络配置。

> Claude Code 可能会自动用默认浏览器打开授权网页。如果打开的不是刚才配置并检查过的指纹浏览器，先不要在那里输入账号。复制本次完整授权链接，到已配置的指纹浏览器环境里打开，再按页面和终端提示完成登录。

授权链接只在用户自己的设备上使用，不发到聊天、不写进进度文件。不同版本的回调方式可能不同，按当前页面和终端提示处理；回调没有完成时先排查，不自行改写授权地址。若默认浏览器就是刚才检查过的环境，无需重复搬链接。

网页授权完成后，按浏览器章节 3.2 单独验证 Claude Code 的实际请求路径。指纹浏览器只负责本次网页授权，不会自动接管 Claude Code 的后续联网。

## 记录进度

将检查时间、设备范围、评分、各项状态和待补项写入 `.local/progress.md`，不把用户数据提交到教程仓库。后续网络、浏览器或设备发生变化时，重查受影响的项；手机首次登录、Claude Code 首次授权分别检查对应部分。
