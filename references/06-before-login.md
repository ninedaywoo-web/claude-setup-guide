# 注册或登录 Claude 前，先检查一遍

电脑网络和指纹浏览器配置完成后，先检查电脑部分，然后直接进入手机配置并检查手机部分。全部适用项完成后，iPhone 默认在 Claude App 用 Google 登录；安卓按[官网 Google Pay 指引](11-android-web-pay.md)提示风险后，在手机浏览器登录官网。已有账号也要检查，不默认先做电脑网页注册。换电脑、换浏览器环境、换节点或网络配置后，检查受影响的项目。

## 给用户看的说明

> 先确认网络和浏览器已经配好，再登录 Claude。
>
> - **电脑系统代理是否关闭，TUN／Tunnel 和全局代理是否都开启？**三项分别核对；本机 HTTP 入口仍保留给 AdsPower。
> - 指纹浏览器是否配置完成，当前打开的是不是准备使用的那个环境？
> - **下一步用 iPhone 完成首次登录与订阅。**手机要单独配网络。Mac 优先让 Codex 用 iPhone 镜像导入同一服务器节点并排查镜像问题；Windows 默认图解与截图带做。小火箭「全局路由」选「代理」，打开连接并核对系统 VPN，再在手机检查实际出口、IPv6／DNS、App 路径和断线行为，不能用电脑结果代替。
> - **Windows 时区是否核对？**关闭自动设置时区，手动选择对应出口地区的时区，按地区规则处理夏令时，保留自动校时。
> - **Mac 时区三项是否都设置好了？**在「系统设置 → 通用 → 日期与时间」关闭自动设置时区，手动选择节点所在城市；再到「隐私与安全性 → 定位服务 → 系统服务」关闭「设定时区」。不要只确认当前显示的城市。
> - **iPhone 时区三项是否都设置好了？**在「设置 → 通用 → 日期与时间」关闭「自动设置」，手动选择节点所在城市；再到「隐私与安全性 → 定位服务 → 系统服务」关闭「设定时区」。暂时不用手机，首次登录或订阅前再补检。
> - **电脑、手机和指纹浏览器的实际时区是否一致，并对应 VPS 实际出口地区？**正常用简体中文就可以。按作者建议，系统语言可将电脑和手机一起改成英文；要改就两台一起改，英文界面可能给日常使用带来不便，也可保留中文。
> - 定位相关的时区设置可能让系统回到所在地时区，例如上海；**请确认上述开关状态，并返回日期与时间页面复查城市。**浏览器检测到的时区也要单独核对。
> - 在已配置的环境记录三个网站的结果：[NetCoffee](https://ip.net.coffee/claude/) 建议约 80 分或更高；[Ping0](https://ping0.cc/) 风险值低于 30 可作可接受参考，优先低于 25；[Scamalytics](https://scamalytics.com/ip) 风险值最好低于 10。三站分别记录，不混算。
> - IPv6 是否已禁用，或确认不会绕过预期线路？
> - WebRTC 是否已禁用，检测时有没有暴露其他公网出口？
> - DNS 查询有没有绕过配置的线路？
> - 节点断开或代理客户端退出后，会不会自动直连？
>
> **下一步：① 让 AI 帮我检查（推荐）　② 我提供检测截图，AI 帮我核对。**
>
> 先完成电脑检查，再配置和检查手机，然后进入 Apple 账户准备与手机 Google 登录。用户明确只做电脑部分时记录手机待补，不把整套交付记成完成。

安卓手机先完成实际客户端、全局路由、出口、DNS／IPv6、浏览器 WebRTC、时区和断线行为等适用检查。下表的 iPhone 镜像、iOS 定位开关、App 请求路径和 Apple 内购项不适用；改为核对安卓实际浏览器的请求路径。付款前另读[安卓官网 Google Pay 指引](11-android-web-pay.md)并展示风险提醒，不能把手机网络通过等同于付款成功。

## AI 怎么执行

到达注册或登录步骤时，按实际设备只展示上面适用的说明和两个选项（安卓用户用官网 Google Pay 分支的说明，不展示 Apple 专属要求），等待用户选择，不直接打开 Claude 注册或登录页面。对话工具支持选项时使用选项；否则用文字，让用户回复 1 或 2 即可。用户已明确要求检查时直接开始。

选择 1：用现有工具读取配置，在实际准备登录的浏览器环境里检测。不能操作某台设备或检测页时，只请用户提供缺失部分的截图或结果。选择 2：核对截图所属的设备、浏览器环境和检测时间；看不到的项目标记为“未验证”。不要因为截图里有高分，就替其他项目填通过。

| 项目 | 核对什么 |
| --- | --- |
| 电脑接管模式 | 系统代理关闭、TUN／Tunnel 开启、全局代理开启，当前目标节点固定；核对实际系统代理、虚拟接口与路由，不以图标单独判通过。本机 HTTP 入口保持可用。 |
| 三处节点一致 | Mac Karing／Windows v2rayN 实际目标节点、AdsPower 经本机 HTTP 入口的出口、手机小火箭使用的节点属于同一服务器线路；分别查配置与实际出口，不凭相同节点名称判一致。 |
| 指纹浏览器 | 环境已保存并打开；HTTP 入口与当前代理客户端实际配置相符，代理实际连通；检测必须在这个环境内完成。尚未配置好时回到浏览器配置章节。 |
| 手机操作方式 | Windows＋iPhone 默认图解、截图／口述核对，有实际可用手机工具才代做；不要求 Mac 镜像。Mac＋iPhone 优先使用 Codex Computer Use + iPhone 镜像。按浏览器与 iPhone 章节 2.1 检查兼容与地区支持、账户与双重认证、Wi-Fi／蓝牙、锁定与距离、连接授权和工具操作权限；有问题先修复重试。记录实际操作能力；不能用时记录具体阻碍、已尝试步骤及替代方式，不默认为让用户自行配置，也不跳过网络验收。 |
| 手机节点、路由与 VPN | 首次手机注册、登录或订阅前，导入同一服务器节点并核对参数；小火箭「全局路由」为「代理」、目标节点正确、连接开启、系统 VPN 已连接。其他客户端核对等效设置。用户明确选择其他模式时，按浏览器章节检查实际路由、出口和泄露后记录；状态未见到时先补检，不能用 VPN 图标代替路由检查。暂不用手机记“不适用（首次注册、登录或订阅前补检）”。 |
| 手机网络实际验收 | 按浏览器与 iPhone 章节 3.1，在手机自己的浏览器检查实际出口、Claude 检测与 Ping0、IPv6／DNS 和排除路由；官方 App 安装后先在未登录状态结合客户端日志核对可观察到的相关请求，登录后再复核。实际使用的 Wi-Fi／蜂窝网络分别记录，未使用的网络标注切换前补检。分别记录节点不可达与关闭 VPN 的测试结果并恢复连接；不能把「代理」写成关闭 VPN 后仍能阻断直连。看不到的结果记“未验证”，手机结果独立于电脑。 |
| 电脑时区 | Mac 逐项核对：①「系统设置 → 通用 → 日期与时间」的自动设置时区已关闭；② 手动选择的城市对应实际节点地区；③「隐私与安全性 → 定位服务 → 系统服务 → 设定时区」已关闭。记录每项状态，再返回日期与时间页面复查实际城市。单独核对浏览器读到的时区，不能用浏览器设置代替系统设置；Windows 按 [Windows 专章](10-windows.md)检查自动时区、手动时区及夏令时，保留自动校时，不能套用 Mac 路径。 |
| 手机时区 | iPhone 首次登录 Claude 或通过 App Store 订阅前，逐项核对：①「设置 → 通用 → 日期与时间 → 自动设置」已关闭；② 手动选择的城市对应实际节点地区；③「隐私与安全性 → 定位服务 → 系统服务 → 设定时区」已关闭。记录每项状态，再返回日期与时间页面复查实际城市。没有手机或暂不使用，记录“不适用（首次登录或订阅前补检）”，不算手机已通过。 |
| 三处时区一致 | 将电脑系统、iPhone 系统、AdsPower 实际时区并排核对，采用与 VPS 出口地区对应的同一时区规则。记录城市／时区标识和偏移；城市名不同但规则等效时说明依据，不只比时钟数字，也不照抄服务器 UTC。语言可保持中文，不作为时区判断依据。 |
| IP 检测评分 | 在拟登录的浏览器环境打开 https://ip.net.coffee/claude/，记录实际分数和检测时间。按教程“约 80 分或更高”的建议核对；不满足建议值时先说明并排查，不写“账号一定安全”。页面不可访问、无分数或量表不同，记录“未验证”，不编造分数。 |
| Ping0 节点检测凭证 | 在同一浏览器环境打开 https://ping0.cc/，按浏览器章节 1.4 记录检测时间、节点名称、出口地区、ASN / 运营商、IP 类型、风控值、原生 IP、共享人数及脱敏截图路径。风控值与 Claude 检测分数分别记录，不混用量表；缺失结果写“未验证”。风险值低于 30 可作可接受参考，优先低于 25。第三方标签只作辅助证据。 |
| Scamalytics | 在 https://scamalytics.com/ip 查询同一次检测的代理出口 IP，记录实际风险分、检测时间和地区，建议低于 10；不要误查本地直连地址或网站示例 IP。无数据写“未验证”。 |
| IPv6 | 记录“已禁用 / 不可用 / 已启用”。已禁用或不可用还要核对是否确实没有浏览器 IPv6 出口；启用时检查是否沿预期线路。不能把“未测到地址”写成“系统已禁用”。发现绕行先修复。 |
| WebRTC | 查看该浏览器环境内 WebRTC 是否禁用，并实际检测是否暴露预期代理之外的公网地址。配置状态和实际测试结果分别记录。 |
| DNS | 结合浏览器安全 DNS、客户端 DNS 规则及检测结果判断查询路径。解析服务商与 VPS 不同、解析器城市不同，本身不能直接判为泄露。不能确认查询路径时标为“未验证”。 |
| 电脑实际出口与断线行为 | 按浏览器章节 1.4 验证实际出口和目标域名路由；分别检查节点不可达与客户端退出，不允许自动直连。先按网络章节核对 Codex 联网依赖，可能中断时提前给用户手动恢复步骤并确认会恢复；无恢复办法则记“未验证”。确认没有登录、付款或其他不能中断的工作后再测，恢复后确认 Codex 可继续。手机按本表「手机网络实际验收」及章节 3.1 单独记录，不套用电脑客户端退出后的行为。 |

先检查，再处理发现的问题。修改系统时区、IPv6 或浏览器配置前，说明改哪里、会影响什么并记录原值，按用户授权操作。不要为了把清单全部勾上，直接重置网络或覆盖原有浏览器环境。

**时区项必须主动提醒并逐项验收。**不要只问“时区改了吗”，也不能只凭一次显示为洛杉矶就写通过。Mac 和 iPhone 分别记录自动设置开关、手动城市、定位服务中的「设定时区」开关，以及返回页面后的复查结果。看不到某个开关时，只请用户补充该设置页的截图或在页面确认，记“未验证”；适用设备的三项设置与复查均确认后，时区项才记通过。系统版本导致路径或名称变化时按实际界面定位；开关无法调整时先排查，不把不可操作直接记为已关闭。只核对相关时区设置，不要求关闭整个定位服务或 Mac 的自动校时。设置、节点地区或网络变化后重查对应项目；时区差异不能被写成确定的封号原因。

**手机网络项同样必须主动带做并逐项验收。**准备在手机使用 Claude 即触发，不以是否订阅为条件。Mac＋iPhone 镜像优先排查到可用，再由 Codex 完成导入和设置；Windows＋iPhone 默认图解与截图核对；确实不可用才按记录的替代方式继续。网络适用项未通过或未验证时先修复／补检，不直接打开手机 Claude 注册、登录或订阅流程。镜像本身不是网络通过的凭证；排查失败可以记录替代方式，网络关卡仍须完成。用户明确跳过按下文保留真实状态处理。主动关闭 VPN 会恢复原网络的设备，要提醒用户先停止 Claude 使用，重新连接并复查后再继续。

检查完成后只展示简短表格：“检查项｜通过／未通过／未验证／不适用｜结果”。记录检测分数、时间、IPv6 实际状态和需要补做的项；公网 IP 脱敏，不保存账号、密钥或授权链接。

发现未通过或未验证的适用项目，先带用户修复或补检，再回到本表。全部适用项已完成后，告诉用户检查结果，再进入注册或登录。用户明确要求跳过时说明尚未核对的项目，保留原状态，不把跳过记成通过。网络检测只能核对配置，第三方评分不能预测封号结果。

## 网络检查完成后，进入 Apple 账户准备与手机登录

网络检查结果先单独反馈给用户。默认路线接下来通过 App Store 订阅 Claude，主动进入 [Apple 充值／订阅前检查](03-apple.md#充值和订阅前先确认-apple-账户情况)：询问老号／新注册／刚接手的成品号及开始使用的时间，按客户反馈提醒新号先正常使用约两天，暂不充值和订阅。不要把这组问题提前合并进上面的网络清单；也不要等充值后才问。

已提供的账户信息和已完成的等待复用本机进度。已有购买受限进入人工支持流程，等待按客服安排。等待期间可以完成手机 Google 登录并在电脑指纹浏览器免费使用 Claude；付款仍按等待安排。不主动改走网页订阅。

## 后续 Claude Code 登录提醒（不属于交付教学）

开始 Claude Code 登录前，先确认指纹浏览器检查结果仍然适用，并核对准备启动 Claude Code 的终端网络配置。

> Claude Code 可能会自动用默认浏览器打开授权网页。如果打开的不是刚才配置并检查过的指纹浏览器，先不要在那里输入账号。复制本次完整授权链接，到已配置的指纹浏览器环境里打开，再按页面和终端提示完成登录。

授权链接只在用户自己的设备上使用，不发到聊天、不写进进度文件。不同版本的回调方式可能不同，按当前页面和终端提示处理；回调没有完成时先排查，不自行改写授权地址。若默认浏览器就是刚才检查过的环境，无需重复搬链接。

网页授权完成后，按浏览器章节 3.2 单独验证 Claude Code 的实际请求路径。指纹浏览器只负责本次网页授权，不会自动接管 Claude Code 的后续联网。

## 记录进度

将检查时间、设备范围、评分、各项状态和待补项写入 `.local/progress.md`，不把用户数据提交到教程仓库。后续网络、浏览器或设备发生变化时，重查受影响的项；手机首次登录、Claude Code 首次授权分别检查对应部分。
