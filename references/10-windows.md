# Windows 带做：从 VPS 到电脑与手机验收

适用于客户使用 Windows 电脑的交付。先通读两篇核心教程，再读本章；Windows 的客户端、权限、网络切换和手机操作按本章执行，服务器部署及账号订阅复用主流程。这里的 VPS 仍选 Linux，不因为客户电脑是 Windows 就购买 Windows Server。

**验证状态：本章已完成流程整理，尚未完成真实 Windows 设备的整套交付验收。**带做时记录实际系统、客户端和内核版本；不能把 Mac 的成功案例或更新脚本测试说成 Windows 已跑通。

## 1. 确认设备与进度

先问电脑系统、手机类型、是否已有 VPS；随后按当前步骤补齐 Windows 版本、x64／ARM64 架构、能否完成管理员授权、当前 VPN 软件与接管方式。可在「设置 → 系统 → 系统信息／关于」查看，不让新手猜架构。确认自己可用的 Google 账号，缺少时按[账号准备](08-google-account.md)继续。

默认电脑路线为 **Windows → v2rayN → AdsPower**。手机是 iPhone 时继续小火箭与 Apple 内购；只有 Android 时，可以先做电脑和手机网络，但需单独确认订阅途径，不能让用户寻找 iPhone 镜像或把 Apple 内购标成完成。

项目检查更新需要 Python 3.9+。Windows 先确认实际可用入口（`py -3`、`python` 或 `python3`），再执行同一更新脚本；没有解释器时按 SKILL 中本版本的缺失处理继续本地教程。更新时保留 `.local/`，不能把私有版替换成公开版。Windows 实际领取、文件占用及更新恢复也需实机确认，Mac 上脚本测试通过不能替代这些检查。

## 2. 先保留 Codex 正在使用的网络

记录旧客户端、当前节点名称、系统代理／TUN 状态和恢复方式，不记录密钥或完整 IP。先让用户知道旧客户端从哪里打开、哪个按钮恢复原连接。不要为了安装新客户端提前退出旧 VPN、删除旧配置、清除系统代理或关闭旧虚拟网卡。

新客户端初次启动时先检查是否会自动接管网络。单独测试阶段只启用新节点的本机 HTTP／SOCKS 入口，保持新客户端 TUN 和自动设置系统代理关闭，保留旧 VPN 的现状；这不是最终交付模式。软件已自动开启接管时先识别归属，不能误关旧客户端。

## 3. 购买与部署 Linux VPS

商家、套餐与图解沿用[网络教程](01-network.md)和[注册购买图解](09-vps-purchase.md)。已有 VPS 就核对现有系统、权限和配置，不重新购买。注册、验证、支付由用户完成。

本机打开 PowerShell，用 Windows OpenSSH 连接 VPS；先检查 `ssh -V`，没有时再引导安装 Windows 的 OpenSSH 客户端。根据服务商实际提供的 SSH 端口、登录用户和密码／私钥选择命令。不要默认所有商家都给 DMIT 格式的私钥，也不要默认端口一定是 22。

```powershell
# 本机 PowerShell：将占位符替换成实际值后执行
ssh -p <SSH端口> <登录用户>@<服务器地址>
ssh -i "<私钥的实际完整路径>" -p <SSH端口> <登录用户>@<服务器地址>
```

上面是两种登录方式，选择适用的一条。路径有空格时保留引号，不假定存在 D 盘。首次连接核对主机指纹；出现已知主机密钥变化时先确认是否重装或更换服务器，不直接删除记录绕过。私钥权限报错按 Windows 文件 ACL 处理，不在 PowerShell 里执行 Mac 的 `chmod`。密码在用户本机输入。

确认终端已进入 VPS 后，按网络教程部署 3x-ui 与 VLESS + Reality。明确标注每条命令在「本机 PowerShell」还是「VPS 的 Linux 终端」执行；`apt`、`systemctl`、`iptables` 等服务端命令不放到本机执行。不为运行这些命令额外安装 WSL。

验收服务运行、入站端口监听与放行，再从面板导出节点链接／二维码。通过本机剪贴板或文件导入客户端，不根据截图抄公钥，不让 AI 猜 O 与 0；敏感链接不进入聊天或进度。

## 4. 安装 v2rayN，导入节点

从 [v2rayN 官方发布页](https://github.com/2dust/v2rayN/releases)选与实际 Windows 系统、架构匹配的稳定包，核对当前发布说明中的运行库与内核要求，不照抄旧截图的压缩包名。解压到用户选择的固定可写目录，不假定 D 盘存在，也不从压缩包内部直接运行。

开启 TUN 时按当前版本完成管理员授权；不因此要求整个 Codex 会话始终以管理员运行。若用户无授权能力，记录阻碍，不将仅系统代理标成 TUN 已完成。

使用当前界面的剪贴板导入入口，核对地址、端口、UUID、传输、Flow、SNI、公钥与 Short ID，固定选中目标节点。读取客户端版本、实际运行内核及版本、本机 HTTP／混合入口和绑定地址。端口以实际监听为准，10808 只是旧图示例；不为 AdsPower 开启局域网共享。

安装与导入的旧图可在[网络教程第七节](01-network.md)找到，按 SKILL 的图文规则打开核对后展示。图中版本或按钮不适用时说明差异，不能用 Mac 截图充当 Windows 操作截图。

## 5. 先单独测新节点，再切换

旧 VPN 仍为 Codex 联网时，让测试请求**明确指定新客户端实际监听的 HTTP／SOCKS 入口**，访问无登录检测页和 HTTPS 网页；用本轮日志核对请求经过新节点，并在本机核对出口属于所选 VPS。PowerShell 调用 curl 时使用 `curl.exe`，避免旧版 PowerShell 的 `curl` 别名；确认请求确实使用指定代理。SOCKS 测试还需核对域名解析方式，不把本地 DNS 解析误当成经代理解析。

延迟数字、VPN 图标、一次 TCP 端口可达都只是辅助信号。检测页打不开或握手失败时先核对服务端、节点参数、两端时间、对应日志和实际内核；Mac 的 Karing 历史修复组合不直接套给 Windows，不凭一条错误降级服务端或换客户端。

旧 VPN 可能同时承载新客户端到 VPS 的底层连接。此时只能记「新节点经当前网络可连」，**还未证明移除旧 VPN 后可用**。保存测到的结果，再进入下面的切换。

单独测试失败且证据表明两客户端存在路由／TUN 冲突时，才考虑短暂断开旧 VPN。先说明冲突依据，并把具体恢复步骤发给用户；用户确认知道如何恢复后再试。不让两个 TUN 同时争抢默认路由，也不通过重置全机网络试错。

## 6. 切换到 TUN＋全局，保留失败恢复办法

切换前记录旧设置，给用户一段按其实际软件名称填写的提醒：

> 接下来需要切换网络，Codex 可能暂时断开。如果新线路连不上，请先关闭【新客户端的 TUN／连接】，再打开【旧客户端】，选择【原节点】，恢复【原来的代理／TUN 设置】。网络恢复后回到这个对话继续；不用等断网后的 AI 来恢复。

准备好后解除旧客户端的网络接管，再启用 v2rayN 的 **TUN＋全局**，固定选择目标节点，**关闭／清除系统代理**，同时保留 AdsPower 要用的本机 HTTP／混合入口。清除系统代理与关闭该监听入口不是一回事。界面名称和路由实际作用以当前版本为准，同时检查例外路由及自动回落规则。

在旧 VPN 已不承载流量的状态下，重新验证 TUN 虚拟接口、路由、浏览器和未显式配置代理的本机新请求的出口；再让用户发送一条新消息，确认 Codex 收到新的回复。检查当前进程残留的代理环境变量是否仍指向旧端口；必要时记录进度并按实际情况重开应用，不盲目清空所有变量。失败优先按约定恢复旧网络，保留错误后继续排查。

## 7. 配置 AdsPower 与电脑自检

按[浏览器章节](02-browser-iphone.md)创建独立环境，系统选实际 Windows，使用适配设备的当前稳定内核。路线为 **AdsPower → v2rayN 的本机 HTTP／混合入口 → 所选 VPS**。核对真实监听地址、端口与认证要求，不能填写 VPS 的 SSH 端口或 VLESS 入站端口。

在这个环境里检查实际出口与目标线路一致、WebRTC、DNS、IPv6。关闭系统 IPv6 不是唯一验证办法；依据实际泄露与路由决定，记录原值，不反复盲改。按自检章节分别记录 NetCoffee、Ping0、Scamalytics，不能只凭评分代替网络验收。

Windows 时区在「设置 → 时间和语言 → 日期和时间」核对：关闭自动设置时区，手动选择对应实际出口地区的时区，保留自动校时。按该地区规则处理夏令时，不把洛杉矶全年固定成 UTC−8。可用 PowerShell `Get-TimeZone` 读取系统时区，再与浏览器及手机实际规则对照；Windows 时区标识与 IANA 名称可能不同，按规则核对。不要让 Windows 用户寻找 Mac 的「定位服务 → 系统服务 → 设定时区」。系统语言可以保留中文。

## 8. 浏览器通过后接手机

**Windows＋iPhone：**Windows 没有 Apple 原生 iPhone 镜像，默认用对应图解逐步指导用户在手机操作，再通过截图／口述核对。若当前环境确有可用的手机操作工具，可先验证操作能力再代做；不承诺 Windows 能运行 Mac 镜像功能，不让用户反复排查 Mac 专属条件。登录、验证码、Face ID 和支付由用户完成。

按[浏览器与 iPhone 章节](02-browser-iphone.md)导入同一服务器节点，小火箭「全局路由 → 代理」，开启 VPN，检查手机实际出口、时区、DNS／IPv6、所用 Wi-Fi／蜂窝网络和断线行为。手机不能填写电脑的 `127.0.0.1`；电脑检查也不能替代手机检查。

**Windows＋Android：**按网络教程的 Android 分支配置兼容的客户端并验收，再与用户确认是否有 iPhone 可用于原定 Apple 内购。没有时说明 Apple 路线暂不能继续；仅在用户选定替代订阅途径后核对对应官方流程，不自行安排网页付款或编造安卓 Apple 内购步骤。可完成的网络工作继续做，订阅保持待确认。

## 9. 接回账号与订阅主线

有 iPhone 且手机网络通过：Apple 账户／礼品卡检查 → 新号约两天等待安排 → 手机 Google 登录 Claude → 可选电脑免费体验 → 手机 Pro 订阅 → 电脑同一账号权益与正常对话。细节按[带做指南](05-ai-walkthrough.md)执行。手机主要用于登录和订阅，电脑网页使用已配置的 AdsPower；不主动展开 Claude Code 教学。

## 10. 交付验收与恢复

将结果记入 `.local/progress.md`，每项有实际证据，未做就写「未验证」：

| 检查 | 完成依据 |
| --- | --- |
| 脱离旧 VPN | 旧客户端不再承载流量，新节点真实出口正确；Codex 新消息能收到回复。 |
| 客户端与浏览器 | TUN＋全局、系统代理关闭；实际 HTTP 入口可用，AdsPower 出口正确，无已观察到的绕行；版本与内核已记录。 |
| 节点故障 | 先停止 Claude 登录／付款等操作，准备手动恢复。客户端保持运行、节点暂不可达时，用无登录检测页的新请求观察是否失败或绕行；恢复节点再验证。不能凭“全局”声称失败必阻断。 |
| 客户端退出 | 单独检查退出后的行为。AdsPower 显式代理失效与系统恢复直连是两种结果；TUN 关闭本身不保证阻断所有直连。存在回落先停止 Claude 使用，修复／明确未解决项，不记“全部通过”。 |
| 重启恢复 | 用户方便时先保存工作和进度，安排恢复办法，再验证重启／重新登录后的客户端权限、TUN、端口、路由、AdsPower 与 Codex。暂不能重启就记待验收，不擅自重启。 |
| 手机与订阅 | 手机单独验收；实际订阅及电脑同账号权益、对话分别确认。Android 未确定付款路线时不标整套完成。 |

会切断 Codex 的故障测试同样要先交代恢复办法；无法安排恢复时保留未验证，不冒险测试。退出客户端后失网可能是残留代理、路由或明确配置的阻断策略，结合实测排查，不能一概称为正常；也不要一键重置网络或清空防火墙。

官方操作参考：[v2rayN 界面说明](https://github.com/2dust/v2rayN/wiki/Description-of-some-ui)、[常见问题](https://github.com/2dust/v2rayN/wiki/Faq)、[Apple iPhone 镜像支持范围](https://support.apple.com/en-us/120421)。软件界面变化时核对当前说明。
